# Repository worlds in the installed ElseMesh engine

Open `index.html` for the repository-world runtime. `worlds.html` remains an alias used by existing owner applications. Repository mode constructs the actual `Engine`, `SceneRenderer`, `Input`, `Player` and native `Colliders`. It does not instantiate the default islands, boat or NetworkDemo.

Use **Open world folder** to select an external repository containing `world.json`, its content addressed snapshot and assets. Public GitHub URLs are resolved once and all data is read from the resulting full commit. Check for update stages a validated revision and displays old/new commit identifiers without replacing the running world. Apply checked update is a separate deliberate action and disconnects the previous session; stale candidates cannot apply. No Git token is requested. `host.active.identity` records world ID, source location, commit when remote, content digest and session ID. External repositories remain content data and do not enter the engine source tree.

**Open hosted world** accepts a same-origin static repository directory such as `/worlds/house/`. It uses the same validated manifest loader as folder and GitHub imports. Credentials, cross-origin hosts, query strings, fragments and unsafe path segments are rejected; requests reject redirects, enforce streamed byte limits and time out. The engine installation and these hosted content directories remain separate artifacts.

`RepositoryWorldHost.load(source)` validates the shared contract, builds a detached native scene and collision set and checks spawn before activation. `activate(loaded)` supports independently validated candidates. A generation guard rejects superseded work. Only a successful candidate swaps scene, collision, terrain and Player together, clears transient input and disconnects the previous session. Failed candidates release their resources and preserve the active world. `disconnect()` clears ephemeral overlays and pending candidates; `dispose()` also releases the active world.

The renderer conversions preserve object hierarchy, imported static GLB primitives/material slots and base color textures, material overrides, terrain and supported imagery, authored features, forest, neon and computers. Native rendering currently omits GLB normal, ORM, AO and emissive texture maps and reports those omissions. Collision is conservative world AABB derived from authored collision settings; transformed concave models do not acquire triangle collision. Doorways and stairs must be authored from separate appropriately collidable parts. This is not a physics hull generator.

WASD walks with the existing ElseMesh Player controller; drag or arrows look, Space jumps, Shift runs. E within three metres of a computer opens its assigned neon controls. Offline power changes are an ephemeral overlay; authored repository content is not changed.

A federated session requires an operator supplied trusted owner node ID plus a separate admission JSON file containing signed content binding and region proof. These are not read from the world repository. The installed session verifier authenticates the signatures and exact content digest before connecting the existing private neon client. The server must expose its existing endpoint at the same origin `/__private-neon`. Public identity display contains only the public node ID and public key. Session power/config/time overlays update presentation while `getAuthoredProject()` returns authored data.

Build: `npm run build` includes the `worlds.html` entry. Browser qualification and final release gates must be recorded separately from a successful build.
